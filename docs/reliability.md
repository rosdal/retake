# Reliability

What Retake does when something goes wrong, and when each case was last tested. Every row either recovers on its own or shows a tray error with one clear log line. Stand-in game = `examples/avsync.rs` (see `docs/sync.md`); automated tests never launch Siege.

| Event | Expected behaviour | How it's handled | Tested |
|---|---|---|---|
| Game crashes | Stop recording; the buffer stays saveable so F9 can still catch the crash moment | The watcher sees the process gone and stops after 5 s; segments stay until the next session starts. A press after the stop saves the last seconds that were recorded | 2026-11-07: stand-in killed, F9 25 s later saved the 18 s before the stop |
| ffmpeg crashes | Restart with backoff; audio reconnects to the new pipes | Watcher backoff 1/2/5 s (Failed after 5 restarts in 10 min). Video and audio ffmpeg restart together with fresh pipes and a new pump, so they keep one origin | 2026-11-07: video ffmpeg killed → back in 2 s; audio ffmpeg killed → whole run back in 2 s |
| Mic unplugged | Mic track continues as silence; tray warning; reattach when it's back | The capture thread ends; the pump keeps writing silence, turns the tray yellow and restarts the capture every 2 s | 2026-11-07, simulated with `mic_device = "No Such Mic"`: one warning listing the real mics, tray yellow, clip keeps a silent Mic track. A physical unplug is still to do |
| Default output device changes | Process loopback follows; device loopback and the default mic follow too | Process loopback is a virtual device Windows re-routes; for `device` and the default mic the pump compares the default device id every 2 s and restarts the capture | Not tested: Windows has no public API to switch the default device from a script. Needs a person |
| Disk below 2 GB free | Stop recording, tray error, don't fill the disk | `DiskGuard` on every poll: below 2 GB the session stops at once and the icon shows Failed; above 3 GB recording may start again | 2026-11-07 with `RETAKE_TEST_FREE_MB_FILE`: 1000 MB → stopped in < 2 s, icon Failed; 5000 MB → recording again 6 s later |
| Clips drive missing | Saves fail with a tray error; the buffer keeps running | The save job fails, a toast says why, the recorder is untouched. A clips folder that was only moved is recreated | 2026-11-07: clips folder renamed → save failed with a toast, recording continued; `raw/` moved away → recreated and saved |
| PC sleeps / resumes | Stop on suspend, restart on resume if the game still runs | `WM_POWERBROADCAST`: `PBT_APMSUSPEND` stops at once; `PBT_APMRESUMEAUTOMATIC` lets the watcher start again | 2026-11-07, both messages sent to Retake's window: stopped at once; recording again 7 s after resume. A real sleep is still to do |
| Display mode change | ddagrab errors → the pipeline restarts | ffmpeg exits on the duplication error; the watcher restarts it with backoff | The restart path is the one tested by killing ffmpeg; on 2026-11-06 a desktop switch (`887a0026`) restarted it within 3 s. A resolution change is still to do |
| Two F9 during a save | Queue; never two concat jobs at once | One saver thread works through presses in order | 2026-11-07: two `--save` 4 s apart → two clips, saved one after the other |
