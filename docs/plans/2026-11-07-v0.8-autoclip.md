# v0.8 Auto-clipping Implementation Plan

> **To execute:** use the `executing-plans` skill. Steps use `- [ ]` for tracking.

**Goal:** the player's kills are clipped automatically, with nothing to set up. After the game closes, Retake reads Siege's Match Replay to learn which kills were the player's, finds the moments new kill-feed rows appear in its own session recording, lines the two up, and cuts kill / 2K / 3K / 4K / ACE clips.
**Architecture:** pure logic in `retake-core::autoclip` (row detector, alignment, grouping, naming) and `retake-core::replay` (r6-dissect JSON → rounds and kills). The binary keeps a **session recording** (the ring buffer's segments copied into `clips/session/` while recording; deleted after analysis), runs `r6-dissect` as a sidecar on the newest replay folder, decodes the kill-feed region at 4 fps from the session file, and cuts clips through the existing saver path. Everything after the game has closed, on the background runner.
**Tech stack:** r6-dissect (Go, MIT) built in CI; ffmpeg crop/scale/gray decode.

## Global Constraints

- The anti-cheat rules (roadmap v0.8 table): no game process access, nothing read from the game while it runs (replay files are read only once the game has closed), nothing drawn over the game.
- Zero setup: no name, no template, no calibration. `autoclip.clip = "every" | "2k" | "3k" | "aces" | "off"`, default `every`.
- A clip is 15 s before the first kill to 3 s after the last, at most 90 s; kills more than 45 s apart split into parts.
- Manual F9 always works.

## Tasks

1. `retake-core::autoclip` (done in this branch): `new_rows`, `align`, `round_clips`, `clip_stem`, tests with synthetic feeds and rounds.
2. `retake-core::replay`: parse r6-dissect's match JSON (`header.recordingPlayerID`, `players[].id/username/teamIndex`, `rounds[].matchFeedback[]` with `type = "Kill"`, `username`, `target`, `headshot`, `timeInSeconds`) into `Round { kills: Vec<(killer, victim, headshot, at)> }` where `at = -timeInSeconds` (the clock counts down; gaps are what matter). Tests on a fixture.
3. Session recording: while recording, every finished segment is appended (stream copy) to `clips/session/<start>.ts` with its wall-clock start, so analysis has the whole match, not just 60 s. Bounded by free space (stops below 10 GB free) and deleted after analysis or after 24 h.
4. Replay folder: find Siege's install from the Ubisoft Connect registry entry or Steam's `libraryfolders.vdf`, then `MatchReplay/`. Only after the game has closed. No new folder after a session with a match → one toast with the setting to enable.
5. Kill-feed scan: built-in regions for 16:9, 16:10, 21:9, 4:3; decode at 4 fps grey from the session file; `new_rows`. Tuned on the real Siege clips in `Videos/SteelSeries Moments`.
6. Wiring: per round, `align` replay kills to rows; the player's matched kills → `round_clips` → saver jobs (existing concat path, from the session file) with names `…_kill`, `…_2K`, …; sidecar JSON with victims, headshots, round, map; then graded and exported by v0.7's queue.
7. Fallback without a replay: none beyond manual F9 in this version (the ONNX kill-indicator model needs labelled footage from real matches; tracked as an issue).
8. r6-dissect sidecar: CI job builds it from source (pinned commit) with Go and ships `r6-dissect.exe` next to `retake.exe`; a parser failure logs "Siege update: auto-clipping paused until Retake is updated" once.

## Not testable here

Real replays need Siege closed and a played match; the 10-match accuracy test and the replay-off test need a person. Synthetic and fixture tests cover the logic; the kill-feed detector is tuned on recorded Siege footage.
