# Retake v0.1 — Skeleton & Tooling Implementation Plan

> **To execute:** use the `executing-plans` skill. Steps use `- [x]` for tracking.

**Goal:** A Rust workspace that builds in CI, runs as a silent tray process, loads and validates `config.toml`, writes logs, and can find, check and safely launch a pinned ffmpeg. Nothing is captured yet.

**Architecture:** Two crates. `retake-core` holds pure logic (config parsing, merging, validation, ffmpeg capability parsing) with no `windows` imports and full unit tests. `retake` is the binary: logging, single-instance mutex, tray + Win32 message loop, hidden top-level window for `WM_ENDSESSION`, and a child-process helper that puts every child in a `KILL_ON_JOB_CLOSE` Job Object.

**Tech stack:** Rust stable (1.97, MSVC), `serde` + `toml`, `thiserror`, `tracing` + `tracing-subscriber` + `tracing-appender`, `tray-icon`, `windows` crate, `tauri-winrt-notification`, `anyhow`. Versions: whatever `cargo add` resolves today (recorded in `Cargo.lock`).

Source of requirements: roadmap doc *Retake — Roadmap v0.0 → v1.0*, tab **v0.1 Skeleton & tooling**; config sections from *Siege Clipper — Design Doc* § Config.

## Global Constraints

- Target `x86_64-pc-windows-msvc`; toolchain pinned to `stable` in `rust-toolchain.toml`.
- `retake-core` must not depend on the `windows` crate (or any Win32 API).
- CI: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, `cargo build --release` on `windows-latest`.
- Release binary: `#![windows_subsystem = "windows"]` — no console window.
- Config file: `config.toml` next to the exe. Unknown keys are errors. Error text format: `<section>.<field> = <value>: <reason>`, e.g. `capture.qp_i = 60: must be 0–51`.
- Logs: `%LOCALAPPDATA%\Retake\logs`, daily rolling, keep 7 files. `--console` also logs to stdout.
- Single-instance mutex name: `Local\Retake`.
- Required ffmpeg features: encoders `hevc_amf`, `av1_amf`, `h264_amf`; filters `ddagrab`, `lut3d`, `cas`.
- ffmpeg pin: a 7.x "full" build from gyan.dev, version and SHA-256 in `third_party/ffmpeg.lock`; binaries unpacked into `third_party/ffmpeg/` (git-ignored).
- Anything outside v0.1 scope goes in a `post-1.0` note, not into the code.

## Decisions made while planning (deviations from the doc, flagged)

1. **Default paths.** The design doc defaults `buffer_dir`/`out_dir` to `D:/SiegeClipper/...`. This machine has no `D:`, so the first run would fail validation. Defaults become `buffer_dir = "buffer"` and `clips.out_dir = "clips"`, resolved relative to the folder that holds `config.toml`, with a comment recommending a fast NVMe path like `D:/Retake/buffer`.
2. **Defaults in one place.** Struct-level `#[serde(default)]` needs a Rust `Default` per struct, which would duplicate the defaults. Instead: parse the embedded `default-config.toml` and the user file into `toml::Table`, deep-merge user over default, then deserialize the merged table into structs with `deny_unknown_fields`. Same behaviour (missing keys get defaults, typos fail loudly), one source of truth.
3. **License:** MIT.
4. **Dev hook for the manual Job Object test:** hidden flag `--dummy-child` spawns `ffmpeg -f lavfi -i nullsrc -f null -` through the child helper.
5. **ffmpeg lookup order:** env `RETAKE_FFMPEG` → `<exe_dir>\ffmpeg\ffmpeg.exe` → `<exe_dir>\..\..\third_party\ffmpeg\bin\ffmpeg.exe` (dev layout, from `target\release`).
6. **GitHub remote + CI run** is outward-facing: everything is built and verified locally first. Creating the GitHub repo and pushing needs the user's OK (Task 8).

## Deviations found during execution

- `check_dirs(&Config)` takes no `base`: `resolve_paths` already made the paths absolute.
- `parse_names` skips legend lines by their `=` token instead of looking for a `------` separator; `-filters` output has none.
- `KILL_ON_JOB_CLOSE` terminates children with exit code 0, so the kill test asserts the child was alive and died within 5 s, not that it failed.
- Child output is split on `\r` as well as `\n` (ffmpeg progress lines end in a bare `\r`), and lines are capped at 4096 bytes.
- `WM_ENDSESSION` runs the shutdown hook inside the window procedure, because the process may be terminated as soon as it returns; the hook runs once whichever way the app exits.
- Added `Win32_Graphics_Gdi` to the `windows` features (needed for `RegisterClassW`); `Error::from_win32` → `Error::from_thread` in windows 0.62.
- ffmpeg 7.1.1 SHA-256 was recorded from the GitHub-release download; gyan.dev's own `.sha256` was unreachable (HTTP 503) at the time, so it is not cross-checked.
