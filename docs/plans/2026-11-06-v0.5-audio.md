# v0.5 Audio capture Implementation Plan

> **To execute:** use the `executing-plans` skill. Steps use `- [ ]` for tracking.

**Goal:** clips carry separate audio tracks — Game (process loopback on the game, or device loopback), Mic, and optional Comms (Discord) — muxed by the recording ffmpeg into the same segments as the video.
**Architecture:** a new `retake-audio` crate captures each source with WASAPI on its own thread and hands PCM to a pump. The pump runs a 10 ms high-resolution timer per source, pads silence so every source delivers exactly 48 000 frames per second of wall time, gates the mic, and writes s16le stereo into a named pipe that ffmpeg reads as an input. Pure logic (silence filler, gate, sample conversion, ffmpeg arguments) lives in `retake-core` with unit tests.
**Tech stack:** Rust 2024, `windows` 0.62 (`Win32_Media_Audio`, `Win32_System_Com`, `Win32_System_Threading`, `Win32_System_Pipes`, `Win32_System_IO`), ffmpeg 9.0.2.

## Global Constraints

- No forbidden APIs (`scripts/forbidden-apis.ps1`, `crates/retake/tests/imports.rs`). Process loopback only needs the game's PID, never a process handle.
- `retake-core` stays free of Windows APIs.
- Audio format on the pipes: 48 000 Hz, s16le, 2 channels. Segments: AAC 256 kb/s per track in MPEG-TS.
- Track order and titles: Game, Mic, Comms. A disabled source is left out, not silent.
- Process loopback needs Windows build 19041+; older builds fall back to device loopback with a warning.
- A pipe write that would block more than 200 ms is dropped and logged; an audio thread never blocks forever.
- Zero setup: the defaults (`game = true`, `mic = true`, `comms = false`, `game_source = "process"`) work without any change.

### Task 1: Pure audio logic in `retake-core`

**Files:**
- Create: `crates/retake-core/src/audio.rs`
- Modify: `crates/retake-core/src/lib.rs`

**Interfaces:**
- Produces:
  - `pub const RATE: u32 = 48_000; pub const CHANNELS: usize = 2; pub const TICK_FRAMES: usize = 480;`
  - `pub struct Timeline` (the silence filler) — `new(hold_frames: u64)`, `push(&mut self, pos: i64, frames: &[i16])` places interleaved stereo frames at stream position `pos` (frames since the run's origin B, from the packet's capture time); `take_due(&mut self, now_pos: u64) -> Vec<i16>` returns every frame from the last emitted position up to `now_pos - hold`, zeros where nothing arrived. Frames before the emitted position are trimmed (counted in `late_frames()`); overlaps keep the first write. So every pipe delivers exactly 48 000 frames per second of wall time and each sample sits where it was captured.
  - `pub struct Gate` — `new(threshold_db: f32)`, `process(&mut self, frames: &mut [i16])`; RMS over 10 ms windows, 5 ms attack, 150 ms release; threshold `0.0` = off.
  - `pub fn to_stereo_i16(src: SampleSource<'_>) -> Vec<i16>` with `pub enum SampleSource<'a> { F32 { data: &'a [f32], channels: usize }, I16 { data: &'a [i16], channels: usize } }`; mono duplicated, >2 channels keep the first two.

- [ ] Write failing tests: filler emits exactly 48 000 frames per simulated second with gaps; real samples come out in order; surplus is capped; gate silences a quiet tail of a sine and passes the loud part; conversions.
- [ ] Run `cargo test -p retake-core audio`, see them fail.
- [ ] Implement; run, see them pass. Commit.

### Task 2: Config and ffmpeg arguments for audio inputs

**Files:**
- Modify: `crates/retake-core/src/config.rs`, `default-config.toml`, `ffmpeg_args.rs`

**Interfaces:**
- Consumes: `CaptureSetup`.
- Produces:
  - `config::GameSource { Process, Device }`, key `audio.game_source` (default `"process"`).
  - `pub struct AudioInput { pub pipe: String, pub title: &'static str }` and `CaptureSetup.audio: Vec<AudioInput>`.
  - `CaptureSetup.origin_us: i64`, the run's origin B in Unix microseconds. With audio: video gets `setpts=(RTCTIME-B)/(TB*1000000)` right after ddagrab (ddagrab's own pts counts from its first frame, which nobody outside ffmpeg knows); each pipe input is `-f s16le -ar 48000 -ac 2 -thread_queue_size 1024 -i <pipe>` (inputs 0..n, timestamps by sample count from B); mapping `-map [v] -map k:a …`; `-c:a aac -b:a 256k`; `-metadata:s:a:k title=<title>`. Without audio the arguments stay exactly as today. (Deviation from the roadmap: no `-use_wallclock_as_timestamps` and no `aresample=async`; both streams share one origin instead.)

- [ ] Snapshot tests for: no audio (unchanged), game + mic, game + mic + comms. See them fail, implement, see them pass. Commit.

### Task 3: `retake-audio` crate — WASAPI sources

**Files:**
- Create: `crates/retake-audio/Cargo.toml`, `src/lib.rs`, `src/wasapi.rs`, `src/activate.rs`
- Modify: workspace `Cargo.toml`

**Interfaces:**
- Produces:
  - `pub enum Source { ProcessLoopback { pid: u32 }, DeviceLoopback, Mic { name: String } }` (`name` empty or `"default"` = default capture device).
  - `pub struct Capture` — `Capture::start(source: Source, on_data: impl FnMut(&[i16]) + Send + 'static) -> anyhow::Result<Capture>`; the callback gets interleaved 48 kHz stereo i16 (converted with `retake_core::audio::to_stereo_i16`). Dropping it stops the thread. `Capture::description(&self) -> &str` (device name + format, for the log).
  - `pub fn process_loopback_supported() -> bool` (build >= 19041).
  - `pub fn capture_devices() -> Vec<String>` (friendly names, for the log).
- Thread: `CoInitializeEx(MTA)`, `AvSetMmThreadCharacteristicsW("Pro Audio")`, event-driven shared mode, `AUTOCONVERTPCM | SRC_DEFAULT_QUALITY`; `SILENT` buffers become zeros; `DATA_DISCONTINUITY` is logged.

### Task 4: Pipes and the audio pump in `retake`

**Files:**
- Create: `crates/retake/src/pipe.rs`, `crates/retake/src/audio_pump.rs`
- Modify: `crates/retake/Cargo.toml`

**Interfaces:**
- Consumes: `retake_audio::{Capture, Source}`, `retake_core::audio::{SilenceFiller, Gate}`.
- Produces:
  - `pipe::OutPipe` — `create(name: &str) -> Result<OutPipe>` (outbound, byte mode, 64 kB, overlapped), `wait_connected(&self, timeout: Duration) -> Result<()>`, `write(&self, bytes: &[u8], timeout: Duration) -> io::Result<bool>` (false = timed out, data dropped).
  - `audio_pump::Pump` — `start(tracks: Vec<Track>) -> Result<Pump>` where `pub struct Track { pub pipe: OutPipe, pub source: Source, pub gate_db: f32 }`; one thread per track: 10 ms waitable high-resolution timer, `SilenceFiller::take_due`, gate, pipe write. Dropping it stops every thread and closes the pipes.
  - `pub fn pipe_name(track: &str, run: u64) -> String` = `\\.\pipe\retake_<track>_<pid>_<run>` (unique per run, so a stuck old pipe never collides).

- [ ] Test: create a pipe, connect a reader in a thread, write, read back; a write with no reader times out instead of blocking. Commit.

### Task 5: Recorder integration

**Files:**
- Modify: `crates/retake/src/recorder.rs`, `crates/retake/src/main.rs`

- Order per run: create pipes → spawn ffmpeg → wait for each pipe to connect (5 s) → start captures and the pump. On ffmpeg exit or stop: drop the pump (closes pipes). Game PID changes restart the run between matches (the respawn path already empties the buffer).
- Game source: `Process` with the first game PID when supported; else `DeviceLoopback` with a warning. Comms: `Discord.exe`'s PID, if running when the run starts; otherwise the track is left out and logged.
- Capture start failure on one source logs a warning and leaves that track silent (zeros), so a missing mic never stops recording.

## Clocks

ddagrab stamps frames with `av_gettime_relative()` minus its first frame's time, so its zero is unknowable from outside. ffmpeg's `RTCTIME` is `av_gettime()` (Unix µs, µs resolution, checked on this PC). The pump converts each WASAPI packet's QPC capture time to Unix µs with the current offset between `GetSystemTimePreciseAsFileTime` and QPC (re-read for every packet, so clock slew never accumulates), subtracts B and places it. Task 6 measures the result.
