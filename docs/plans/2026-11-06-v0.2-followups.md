# Retake v0.2 follow-ups — Implementation Plan

> **To execute:** use the `executing-plans` skill. Steps use `- [ ]` for tracking.

**Goal:** Close the open v0.1/v0.2 roadmap items that can be built on the dev laptop: a complete anti-cheat CI guard, zero-setup capture defaults (monitor, encoder, fps, drive picked automatically), game-time quiet mode, and the Siege recording-setup check.

**Architecture:** Decisions stay pure in `retake-core`: an `Auto<T>` config value, encoder/fps/output/drive pickers, a quiet-mode gate, and a Siege settings checker. The binary gathers facts (GPU vendor, monitors with their `HMONITOR`, Siege's window, fixed drives with bus type and seek penalty, Siege's settings files) and feeds them in. The ffmpeg command is now built per session from a resolved `CaptureSetup`, so the monitor can follow Siege's window. A small background runner, gated by quiet mode, runs the setup check: its first job.

**Tech stack:** Rust stable; new dev-dependency `object` (PE import table); `windows` 0.62 gains `Win32_System_Ioctl`, `Win32_System_IO`, `Win32_System_Com`. Pinned ffmpeg 7.1.1.

Source: roadmap tabs **v0.1** (CI anti-cheat guard) and **v0.2** (AV1 stays a gaming-PC check; *Recording setup*: fps = refresh, setup check, zero-setup defaults; *Game-time quiet mode*). Anti-cheat rules (v0.8 tab) apply.

## Global Constraints

- All v0.1–v0.3 constraints hold (`retake-core` has no `windows` dependency; CI = fmt, `forbidden-apis.ps1`, clippy `-D warnings`, tests, release build; config errors `<section>.<field> = <value>: <reason>`).
- No audio on the dev laptop ([[no-audio-on-laptop]]): live runs keep `clips.sound_cue = false`.
- Anti-cheat: Siege's process is never opened (rule 1). Finding Siege's window uses `EnumWindows` + `GetWindowThreadProcessId` + `MonitorFromWindow` only (no process handle). Siege's settings file is read **only while Siege is not running** (rule 4).
- New installs default to `"auto"` for `capture.output`, `capture.fps`, `capture.encoder`, `capture.buffer_dir`, `clips.out_dir`. Existing `config.toml` files keep their explicit values.
- Monitors and encoder come from DXGI adapter 0, as before (v0.2 Decision 6).

## Decisions (flagged)

1. **Import-table check instead of scanning dependency sources.** The `windows` crate *defines* `ReadProcessMemory` and friends, so scanning dependencies' source can only fail. What matters is what the shipped exe links: an integration test reads `retake.exe`'s PE import table (via `object`) and fails on any forbidden import. Source scanning (`forbidden-apis.ps1`) stays for constants like `PROCESS_VM_READ`.
2. **`OpenProcess` rule:** allowed only in files listed in the script's `$openProcessAllowed` (empty today; nothing calls it), and any file that calls it must not name a `PROCESS_*` access right other than `PROCESS_QUERY_LIMITED_INFORMATION`.
3. **Encoder from the GPU vendor** (adapter 0): AMD → AMF, Intel → QSV, NVIDIA → NVENC, anything else → startup error naming the vendor id. Checked on this laptop: QSV records from `ddagrab` with `-init_hw_device d3d11va=dx -init_hw_device qsv=qs@dx -filter_hw_device dx` + `hwmap=derive_device=qsv,format=qsv`; CQP is QSV's default. QSV's I/P QPs come from `-q:v {qp_p} -i_qfactor 1 -i_qoffset {qp_i − qp_p}`. NVENC here fails because the display is on the Intel GPU (no NVIDIA-driven output); its args (`-preset p1 -tune ll -rc constqp -init_qpI -init_qpP`) are untested → gaming-PC issue. AMF args are unchanged.
4. **fps = "auto"** → the largest allowed rate (60, 120, 144, 165, 240) ≤ the monitor's refresh + 1 Hz; unknown refresh → 60.
5. **output = "auto"** → the monitor Siege's largest visible top-level window is on, else the primary monitor. Siege's window usually appears after the 5 s start debounce, so while recording with `output = "auto"` the recorder checks every poll (2 s) and restarts ffmpeg once on the right monitor (the buffer is emptied, as on any respawn).
6. **Drives:** `buffer_dir`/`out_dir = "auto"` → `<drive>\Retake\buffer` and `<drive>\Retake\clips` on the fixed drive ranked best: among drives with ≥ 100 GiB free, NVMe > SSD > HDD > unknown, then most free; if none has 100 GiB, the one with most free. Speed from `IOCTL_STORAGE_QUERY_PROPERTY` (adapter bus type 17 = NVMe; seek penalty false = SSD), opening `\\.\X:` with no access rights.
7. **Quiet mode** = a pure `QuietGate`: background jobs may start only while Siege isn't running and ≥ 30 s after it closed. A `Background` runner thread runs queued jobs one at a time, checking the gate before each, so a job already running finishes (at most one). The Status tab doesn't exist until v0.9; quiet mode is logged on change instead.
8. **Setup check:** reads every `Documents\My Games\Rainbow Six - Siege\*\GameSettings.ini` (Documents via `SHGetKnownFolderPath`, so OneDrive redirection works) as a background job: at startup and after each session. Warns (log) when `LensEffects` or `DOF` is non-zero — the two key names confirmed by a [Steam guide](https://steamcommunity.com/discussions/forum/29/3821910756550676421). Motion blur and HDR key names aren't known, so every key whose name contains `blur` or `hdr` is logged with its value; confirming them is a gaming-PC issue.
10. **Found during Task 1: the exe imported `SendInput`**, via `muda` 0.21.2 (the menu crate under `tray-icon`), which simulates Ctrl+C/X/V for its predefined Copy/Cut/Paste items. Retake never created those, but the import broke rule 5. The user chose to replace the tray crates: `tray.rs` now uses `Shell_NotifyIconW` + a `TrackPopupMenu` built per right-click, re-adds the icon on `TaskbarCreated`, and removes it on exit. `tray-icon` and `muda` are gone from `Cargo.lock`. The guard script skips `tests/imports.rs` (it lists the names) and checks paths with forward slashes.
9. **Commits local; push/PR with the user's OK.** Branch `feat/v0.2-followups`, stacked on `feat/v0.3-clip-save`.
